feat: sistema de autenticação completo, melhorias de desempenho do frontend, arquitetura Docker separada e correções de segurança

Problemas identificados e soluções aplicadas:

- Desempenho crítico do Next.js em Docker
  * Problema: compilações de 4-5 minutos e timeouts ao carregar as páginas
  * Causa raiz: polling agressivo (webpack watchOptions) e sincronização dos node_modules via volume
  * Solução: remoção total da configuração de polling no next.config.mjs e isolamento dos node_modules com volume anónimo (/app/node_modules) + comando de arranque 'npm install && npm run dev'
  * Resultado: compilações em segundos, hot reload instantâneo

- Erros de comunicação entre frontend e backend
  * Problema: frontend não encontrava o backend (next not found, 429 Too Many Requests)
  * Solução: separação dos serviços em dois docker-compose.yml independentes ligados por uma rede externa 'clinica-network'; ajuste do rate limiting para 100 req/min em desenvolvimento
  * Resultado: comunicação fiável, sem falsos bloqueios

Funcionalidades implementadas:

- Página de login (/login)
  * Formulário com email e senha, feedback de erro e estado de carregamento
  * Redirecionamento automático para o painel do role após login bem-sucedido
  * Utilizador autenticado é redirecionado para a raiz se tentar aceder ao login novamente

- Recuperação de senha (forgot/reset password)
  * Página /forgot-password para solicitar link de recuperação
  * Geração de token JWT no backend (visível nos logs para desenvolvimento)
  * Página /reset-password?token=... que permite definir nova senha
  * Redirecionamento para /login após redefinição bem-sucedida
  * Fluxo completo testado com sucesso (desde o pedido até ao login com a nova senha)

- Proteção de rotas com middleware (frontend/middleware.ts)
  * Bloqueia acesso a rotas privadas sem token (cookie access_token)
  * Redireciona utilizadores autenticados que acedem a /login, /forgot-password ou /reset-password
  * Lista de rotas públicas configurável (publicRoutes)

- Contexto de autenticação (AuthContext)
  * Carrega o utilizador atual via /auth/me se existir token
  * Expõe funções loginSuccess e logout para toda a aplicação
  * Persistência do token em localStorage + cookie (path=/; max-age=7d)

- Estrutura de páginas por role
  * /admin, /medico, /paciente, /recepcionista (páginas placeholder)
  * Preparadas para receber dashboards e funcionalidades específicas

Arquitetura final:

- Backend (NestJS + Prisma + PostgreSQL) no docker-compose.yml raiz (apenas db + app)
- Frontend (Next.js 14 + Tailwind) com docker-compose.yml próprio na pasta frontend/
- Rede externa 'clinica-network' para comunicação entre serviços
- Documentação Swagger em /api/docs
- Endpoints de perfil, dashboards, relatórios e paginação já implementados

Lições aprendidas:

- Evitar comandos de substituição (replace) no PowerShell para ficheiros de código (risco de linhas coladas)
- Isolar node_modules com volume anónimo em Docker para evitar conflitos com o host
- Remover polling do Next.js ao usar volumes Docker (basta o sistema de ficheiros nativo)
- Usar rede externa do Docker para comunicação entre serviços independentes
- Testar o fluxo completo de autenticação (login, logout, forgot, reset) antes de cada commit
